## Context

CoTend 项目同时包含公开受跟踪文件、Git 忽略的本地治理文件和仓库外部验收证据。
一次接手核验只查看了 `git status`，没有联合操作写入记录和忽略文件变化。

## Observable Failure

AI 声称本轮没有修改任何项目文件，但相关忽略治理文件具有统一的新修改时间，并且
出现了新的 review、knowledge、decision、STATUS 和 Plan Tree 内容。

## Mistaken Claim Versus Actual State

- mistaken: Git 工作树干净，因此没有文件变化；
- actual: Git 只报告其可见的受跟踪和未忽略路径，忽略治理文件仍可能被写入。

## Cause And Impact

Primary cause: `framework_gap_or_ambiguity`.

把版本控制状态误当成完整文件系统变化证明，会让用户无法准确判断本轮写入范围，
破坏交接、审查和外部审计的可信度。

## Missed Detection

- 没有保留操作级写入回执；
- 没有检查相关忽略治理文件的时间戳或内容哈希；
- 没有把公开受跟踪文件、忽略治理文件和外部 UAT 分开申报。

## Correction

Acceptance/Test Harness 和 Project Init 以真实 VCS 差异加操作写入回执确定变化集；
交接快照同时记录已知相关忽略治理文件。

## Reusable Guard

只有在 Git 证据、操作写入回执以及任务相关忽略文件的变化证据共同支持时，才能
声称“没有文件变化”；否则必须按载体类别准确申报。

## Validation

CoTend 治理语言验证器把 VCS 变化与写入回执合并，Session Handoff 快照要求记录
相关忽略治理文件。新增 v1.76 合同测试验证该规则仍由原生 owner 承接。
