# Tooling Mode: Retire

1. Identify active project/runtime use and direct dependents from current
   evidence; do not enumerate unrelated catalog or inventory bodies.
2. Choose replacement, rollback, archive-only retention or full removal.
3. Obtain authority before uninstalling, deleting data, disabling shared
   runtime, changing network/service contracts or affecting releases.
4. Verify the project without the capability and preserve rollback/history
   evidence.
5. Set adoption, runtime and freshness independently. `retired` is a runtime
   state, not proof that the former adoption was wrong.

Missing dependency/rollback evidence stops removal. Retire does not load
inventory, discovery, evaluation, adoption or refresh bodies to guess it.
